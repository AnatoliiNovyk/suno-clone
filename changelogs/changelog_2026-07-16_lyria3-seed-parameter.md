# changelog_2026-07-16_lyria3-seed-parameter

## Зміна
Додано параметр **Seed** (відтворюваність генерації) на сторінці «Розширений»:

- `python-service/main.py`: `GenerateRequest` отримав `seed: Optional[int]`. Виклик Lyria винесено в хелпер `_create_interaction()`, який передає `generation_config={"seed": seed}` лише коли seed заданий. **Fallback:** якщо модель відхиляє `generation_config` (як вона робить із `mime_type`), помилка з `generation_config`/`seed`/`invalid_request` перехоплюється і виклик повторюється без seed — параметр ніколи не ламає генерацію. `seed` прокинуто у фонову задачу.
- `suno-clone/src/lib/generateApi.ts`: у `GenerateMusicPayload` додано `seed?: number`.
- `suno-clone/src/pages/AdvancedPage.tsx`: поле «Seed» (числове, необов'язкове) із підказкою «однакове число + опис → однаковий трек; змініть seed для варіації». Валідація — лише цифри; невалідне значення підсвічує поле і блокує кнопку. Передається лише коли заповнене й валідне. Проста сторінка «Створити» без змін.
- `CLAUDE.md`: у флоу генерації згадано опційний `seed`.

## Як було до зміни
Генерація керувалась лише промптом/жанром/настроєм/negative-prompt — усе природномовне. Жодного способу отримати **той самий** трек повторно чи свідомо згенерувати варіації того ж задуму не існувало: кожен запуск давав непередбачуваний результат, бо seed обирала модель.

## Що покращує зміна
- `seed` — це справжнє поле API Lyria 3 (`generation_config.seed`, «Seed used in decoding for reproducibility»), а не текстовий хак у промпті. Задавши його, користувач фіксує звучання (той самий seed + опис = той самий трек) або керовано отримує варіації, змінюючи число.
- Безпечно за замовчуванням: fallback гарантує, що навіть якщо конкретна прев'ю-модель не підтримає `generation_config`, генерація все одно пройде (у логах сервіса — `[WARN] retrying without seed`), а не впаде з 400 і поверненням кредитів.
