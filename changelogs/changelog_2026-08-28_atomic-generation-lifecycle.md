# Атомарний життєвий цикл генерації

Раніше фонове завдання генерації оновлювало статус треку та повертало кредити
безумовно. Якщо reaper у той самий момент позначав завислий трек як помилковий,
користувач міг отримати подвійне повернення кредитів або доступ до вже
відшкодованого аудіо.

Тепер усі переходи статусів виконуються як compare-and-swap для очікуваних
станів. Кредити повертає лише виконавець, який успішно позначив трек як
`failed`, а аудіо, завантажене після програної гонки, видаляється зі Storage.
API також перевіряє межі параметрів незалежно від клієнтської форми.
